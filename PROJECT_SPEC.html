TawBayin Badminton POS

A full-stack, responsive Point of Sale and eCommerce catalog system customized for managing inventory, cash transactions, vouchers, and rewards loyalty.

📋

1. Project Overview

TawBayin Badminton POS provides Badminton retailers with a high-performance portal. It bridges catalog management and instant store checkout registers, validating stock availability instantly. State is managed on the client dynamically using Zustand, supported by a transactional MySQL backend.

Core System Next.js 15 (App Router)
Currency Mode Thai Baht (฿)
Support Assistant n8n Chat Overlay

5. Functional Requirements

5.1 Authentication & Profile

Users log in with email/password credentials. Password verification uses bcryptjs. Sessions are persisted in browser HTTP-only cookies (`token`).

Every 30 seconds, client state performs auto-session polling via `/api/auth/me` to refresh display fields and point totals.

5.2 POS Storefront & Product Catalog

Displays active item cards including price and stock labels. Users search using fuzzy matching keywords and filter by categories (Rackets, Shuttlecocks, Shoes, etc.).

Stock Checking: Item cards block adding quantities higher than database stock values. Cart forms disable checkout triggers if items are out of stock.

5.3 Vouchers & Reward Points

Promo Vouchers

Validates expiration dates and minimum subtotal thresholds. Types support percentage (capped at 100% max) or flat Baht reduction values.

Loyalty Rewards

Redemption ratio of 10 points = ฿1 discount. Accrual rules add 1 point for every ฿10 spent on the final checkout total.

5.4 Checkout Calculations

Calculations run sequentially on both client and server checks:

Subtotal = Sum(Item Qty * Price)

Total Discount = Voucher Discount + Points Discount

Tax (10%) = (Subtotal - Total Discount) * 0.10

Final Total = (Subtotal - Total Discount) + Tax

5.5 n8n Customer Support Assistant

An interactive floating chat bubble is injected in the browser window. When operators open it, the chatbot communicates directly with an n8n webhook workflow to answer POS usage questions and guide the cashier on store policies.

6. Non-Functional Requirements

🔒 Security & Hashing

Passwords hashed using bcryptjs. API endpoints block unauthorized queries. JWT tokens use secure HttpOnly settings to prevent XSS attacks.

🔄 Database Constraints

Unique keys for email, products, and voucher codes. RESTRICT constraints prevent deleting products or cashiers containing sales transaction logs.

⚡ Speed & Connection Pools

MySQL connections use a pool to avoid leaks. Key API listings (products and sales) utilize search query pagination for fast responses.

📱 Visual Aesthetics

Tailwind CSS v4 layouts, clean transitions, loading state icons, and interactive SweetAlert2 validation messages.

7. Database Schema (MySQL)

mysql_schema.sql 
CREATE TABLE IF NOT EXISTS users (
  id INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(255) NOT NULL,
  email VARCHAR(255) NOT NULL UNIQUE,
  password VARCHAR(255) NOT NULL,
  role ENUM('admin', 'user', 'cashier') NOT NULL DEFAULT 'user',
  points INT DEFAULT 0,
  image VARCHAR(255) DEFAULT NULL,
  createdAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updatedAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE IF NOT EXISTS products (
  id INT AUTO_INCREMENT PRIMARY KEY,
  title VARCHAR(255) NOT NULL UNIQUE,
  description TEXT DEFAULT NULL,
  price DECIMAL(10,2) NOT NULL DEFAULT 0.00,
  stock INT NOT NULL DEFAULT 0,
  category VARCHAR(100) DEFAULT 'Uncategorized',
  image VARCHAR(255) DEFAULT NULL,
  createdAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updatedAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE IF NOT EXISTS vouchers (
  id INT AUTO_INCREMENT PRIMARY KEY,
  code VARCHAR(50) NOT NULL UNIQUE,
  type ENUM('percentage', 'fixed') NOT NULL,
  amount DECIMAL(10,2) NOT NULL,
  minTotal DECIMAL(10,2) DEFAULT 0.00,
  expiresAt DATETIME DEFAULT NULL,
  createdAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updatedAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE IF NOT EXISTS sales (
  id INT AUTO_INCREMENT PRIMARY KEY,
  total DECIMAL(10,2) NOT NULL,
  subtotal DECIMAL(10,2) NOT NULL,
  tax DECIMAL(10,2) NOT NULL,
  discount DECIMAL(10,2) DEFAULT 0.00,
  paymentType VARCHAR(50) NOT NULL,
  voucherCode VARCHAR(50) DEFAULT NULL,
  cashierId INT DEFAULT NULL,
  createdAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (cashierId) REFERENCES users(id) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE IF NOT EXISTS saleitems (
  id INT AUTO_INCREMENT PRIMARY KEY,
  saleId INT NOT NULL,
  productId INT NOT NULL,
  quantity INT NOT NULL,
  price DECIMAL(10,2) NOT NULL,
  FOREIGN KEY (saleId) REFERENCES sales(id) ON DELETE CASCADE,
  FOREIGN KEY (productId) REFERENCES products(id) ON DELETE RESTRICT
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

8. API Endpoint Reference

Authentication

POST /api/auth/register Creates a cashier account
POST /api/auth/login Authenticates, sets JWT cookie token
GET /api/auth/me Returns user session status

Products Inventory

GET /api/products?category=&search=&lowStock= Lists products with filters
POST /api/products Creates a new product
PUT /api/products Updates stock/categories/prices
DELETE /api/products?id={id} Deletes product unless referenced in sales

Checkout & Sales

GET /api/sales?cashierId=&startDate=&includeDetails=true Lists sales history records
POST /api/sales Performs checkout under transaction
DELETE /api/sales?id={id}&restoreStock=true Deletes record and optional stock rollbacks

CRM Users & Rewards

GET /api/users?role=&search= Lists registered cashiers and metrics
PUT /api/users/[id] Updates user profile, role, and details
POST /api/users/update-points Adds earned loyalty points (Baht total / 10)
POST /api/users/redeem-points Deducts points used for billing discount

11. Technical Architecture

The project employs a structured three-tier full-stack application flow running inside the Next.js runtime:

1. Client / Presentation Layer

Handles catalog searches, shopping cart logic, and theme selectors. Context values like auth details, active points, and item catalogs are cached in Zustand client stores.

2. API Controller / Middleware Layer

Written as App Router API endpoint routes `/app/api`. Performs parameters validation, parses JWT HttpOnly token session values, and returns JSON payloads.

3. Storage Layer

A relational MySQL database linked via `mysql2/promise` connection pools. Enforces constraints (unique codes/emails) and processes checkout transactions safely using ACID properties.
